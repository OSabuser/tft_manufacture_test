## Принятые решения

- **Звук** — I2S: SAI1 → MS4344 → LTK5129. MQS и `VOLUME` на новой плате не используются.
- **SDRAM** — целевой чип W9825G6KH-6. Сначала все тесты гоняем на Micron MT48LC16M16A2P-6A,
  чтобы исключить ошибки инициализации.
- **QSPI** — W25Q128, как на старой плате.
- **Пины EXT_IN1 (EMC_39) и LCD_DCDC_G (SD_B1_05)** переносим только после углублённого
  тестирования (фаза 0) и по его данным.

## Справка: как можно стробировать чтение

Сейчас оба контроллера стробируют чтение через петлю на DQS-паде. Это даёт максимальную частоту,
но пад должен оставаться неподключённым. Если пад занят, можно перейти на внутреннюю петлю
ценой снижения частоты.

| Контроллер | Режим | Пад DQS | Частота | Для нас |
| --- | --- | --- | --- | --- |
| SEMC | `MCR.DQSMD=1` — петля через DQS-пад (сейчас) | занят, должен быть свободен | до 166 МГц (сейчас ~136 МГц) | текущая конфигурация |
| SEMC | `MCR.DQSMD=0` — внутренняя петля | **свободен** (EMC_39 можно использовать как GPIO) | ниже: задержка пада и платы не компенсируется. Предел — по даташиту IMXRT1050CEC, ориентир ≤133 МГц, **проверить** | запасной вариант, если EXT_IN1 останется на EMC_39 |
| FlexSPI | `RXCLKSRC=01b` — петля через DQS-пад (сейчас, FCB 0x0C = 1) | занят, должен быть свободен | до 133 МГц (FCB 0x46 = 7) | текущая конфигурация |
| FlexSPI | `RXCLKSRC=00b` — внутренняя петля | **свободен** | RM: «low frequency clock for boot up usage». Ориентир ~60 МГц, **проверить** | XIP замедлится примерно вдвое. Вариант только на крайний случай |
| FlexSPI | `RXCLKSRC=11b` — строб от флеш-памяти | вход | максимальная | W25Q не выдаёт DQS, недоступно |

Источники: RM Rev.4, поле `SEMC_MCR[DQSMD]`, гл. 27.5.14.1, `FLEXSPI_MCR0[RXCLKSRC]`.
Предельные частоты для внутренней петли указаны в даташите, а не в RM. Даташит нужно положить
в `docs/mimxrt1052/` вместе с NXP Hardware Development Guide.

Режим можно выбрать отдельно для каждого контроллера. SEMC настраивается в DCD и `sdram.c`,
поэтому режим легко менять. FlexSPI настраивается в FCB и в `configure-memory` при прошивке через blhost.
Там переход на `00b` заденет всех: производственную прошивку, bootloader и XIP tft_app.

## Фаза 0 — Углублённое тестирование SDRAM и FlexSPI

**Цель.** Получить данные, достаточные для решения по DQS-падам и конфигу SEMC.
Для контроля используем старую плату. Память на всех платах — Micron.

### 0.1 Аудит текущей конфигурации SEMC (анализ, без железа)

- Разобрать `dcd.bin` и `sdram.c` по полям, перевести циклы в наносекунды на фактической частоте SEMC
  (PFD2 = 528·18/35 = 271,5 МГц, /2 ≈ 135,8 МГц, такт 7,37 нс) и сравнить с даташитом MT48LC16M16A2 -6A.
- Отдельно проверить места, которые расходятся с DCD от EVK:
  `SDRAMCR2 = 0x00020201` (у нас SRRC=1, REF2REF=2, у EVK `0x00010920`: SRRC=0x20, REF2REF=9)
  и `SDRAMCR3` (refresh-burst REBL). REF2REF около 3 тактов (~22 нс) выглядит
  меньше tRC/tRFC ≈ 60–66 нс. Выяснить по RM, что это поле реально ограничивает, и нужно ли его исправлять.
- Результат — таблица «регистр / поле / значение / нс / требование Micron / требование W9825 / вывод»
  в `docs/hardware/new_board_v3.2/SEMC_TIMING.md`. Эта же таблица станет входом для фазы 1.
- ✅ **Выполнено.** Итог: refresh в DCD в 2,9 раза медленнее спецификации (полный цикл 184 мс вместо 64 мс),
  REF2REF = 22 нс при tRFC ≥ 60 нс, у DCD и `sdram.c` разные конфиги refresh.
  PLL2 PFD0/1/3 обнуляются. Кандидат на исправление и тест удержания (retention) —
  в §5–6 SEMC_TIMING.md. Тест удержания добавлен в `hil_sdram_stress`.

## G0 — Точка решения

По итогам фазы 0 выбираем один из вариантов:

| Если… | Решение |
| --- | --- |
| Включённый IN1 ломает SDRAM **или** есть заметная деградация | Запрос схемотехнику: перенести EXT_IN1 на AD_B1_05/06, пад EMC_39 оставить свободным. На текущих платах временно использовать DQSMD=0 на частоте, которую подтвердил тест |
| IN1 на SDRAM не влияет | Всё равно переносим: при DQSMD=1 прочитать EXT_IN1 нельзя в принципе. Альтернатива — DQSMD=0 насовсем, если тест подтвердит запас |
| LCD_DCDC_G | Цепь убрать или перенести. FlexSPI остаётся на 01b/133 МГц (FCB не трогаем), если по 0.3 нет проблем |
| Аудит SEMC (0.1) выявил нарушения таймингов (**да**: refresh, REF2REF) | Свой DCD по SEMC_TIMING.md §7 (фаза 1) для **обеих** ревизий. Перед выпуском — матрица на старой плате, это регресс-риск для платы, которая уже выпускается |

Любая правка DCD затрагивает HAB-образы `firmware_test` и `tft_app` и `bsp_sdram_configure()` в bootloader.
Любая правка FCB затрагивает `configure-memory` в производственной прошивке и SWD-путь.

## Фаза 1 — Свой DCD и W9825G6KH

1. ✅ Даташит W9825 лежит в `new_board_v3.2/`, колонка в `SEMC_TIMING.md` заполнена. Один набор таймингов
   подходит обоим чипам (§5, §5.1): ID у SDRAM нет, поэтому конфиг должен быть общим.
2. **DCD Tool в `TFT_Board.mex`.** Выигравший в фазе 0 конфиг переносим в Config Tools,
   результат — `bsp/generated/dcd.c`. По итогам G0 DCD **два** (совместимость ревизий не цель):
   старая плата — `candidate` (DQSMD=1), V3 — `candidate_dqsmd0` (DQSMD=0, EMC_39 = GPIO под EXT_IN1).
   Оба на 135,77 МГц, FCB без изменений (DQS_TEST_REPORT.md §5). Пользователь делает это в Config Tools, я готовлю
   точный список команд.
3. **Конвейер:** рецепт `just build::dcd` собирает из `dcd.c` файл `tools/host/dcd/dcd.bin`
   (SPSDK-скрипт) для HAB-yaml. Host-тест проверяет, что `dcd.bin` совпадает с массивом.
4. **bootloader:** `bsp_sdram_configure()` исполняет массив из `dcd.c` интерпретатором из фазы 0.2.
   Ручной порт регистров удаляется.
5. Выпуск: новые HAB-образы `firmware_test` и `tft_app`, новый bootloader (это затрагивает обе ревизии платы).
6. **Проверка на железе:**
   - `firmware_test` и bootloader на старой плате (регресс);
   - сокращённая матрица фазы 0 на платах с W9825 (финальный конфиг, IN1 во всех состояниях);
   - soak;
   - тест удержания с нагревом.
7. 🔴 **Блокер закрытия фазы 1 — прогон при +50 °C на V3** (решение пользователя 2026-09-25; −10 °C
   проверить нечем). Финальный DCD на W9825 и Micron:
   - SDRAM: лесенка `dqsmd0` (135,77…163,86 МГц) — край не ниже 158 МГц, рабочая частота чисто;
     удержание с refresh;
   - FlexSPI: `matrix` и `dll` — окно при RXCLKSRC=1/133 МГц заметно не уже 0…23.
   Если край SDRAM уйдёт — снижаем только частоту SEMC в DCD V3.
8. Вопрос закупке: промышленный класс SDRAM (W9825G6KH-**6I**), см. SEMC_TIMING.md §5.2.

## Фаза 2 — Ревизия платы в BSP

1. **Решение D1 — нужна ли одновременная поддержка старой и новой плат.** `firmware_test`
   работает с платами по рекламациям, значит, скорее всего, нужны обе. Предложение:
   - `bsp_board_rev()` определяет ревизию во время работы: опрос BM8563 (0x51) на LPI2C1.
     На старой плате AD_B1_00/01 не подключены, опрос безопасен;
   - в `TFT_Board.mex` общая группа пинов плюс группы `InitPins_RevLegacy` / `InitPins_RevV3`
     для конфликтующих пинов (LCD_MODE/U-D/DITHB, звук, EXT_IN);
   - одна сборка `firmware_test` на обе ревизии. Bootloader от ревизии не зависит: LED, кнопки, SD и QSPI у ревизий общие.

   Альтернатива — ревизия задаётся при сборке (`BOARD_REV`), по бинарю на ревизию.
2. Договориться об имени ревизии в коде: V3.1 по схеме или v3.2 по ветке.
3. На dev- и HIL-платах запаять X3 (SWD).
4. Host-тест логики выбора ревизии (мок I2C).
