# Отчёт: SDRAM и DQS-пад SEMC на старой плате и V3 (фаза 0)

> Дата прогонов: 2026-09-25. Обе платы с SDRAM Micron MT48LC16M16A2P-6A, комнатная температура.
> Прошивка `tests/target/hil_sdram_stress`, хост `tools/hil/08_test_sdram_stress.py`,
> варианты DCD — `tests/target/hil_sdram_stress/dcd/` (README там же).
> Сырые данные: `build/target-debug/hil_sdram_stress_report_{legacy,v3}.json`.
> Контекст: [BOARD_DIFF.md §4.1](BOARD_DIFF.md), [SEMC_TIMING.md](SEMC_TIMING.md), [PLAN.md](PLAN.md) (G0).

## 1. Итог

1. **На V3 включённый EXT_IN1 полностью ломает SDRAM при DQSMD=1** (строб через DQS-пад EMC_39).
   IN1 включён: ошибка почти в каждом слове (PRNG — 8 338 776 из 8 388 608), все 16 линий DQ,
   с первого же адреса. Меандр 5 Гц — примерно половина ошибок (IN1 включён половину времени).
   Под это попадают production-DCD (`legacy`) и `bsp_sdram_configure()`: там тоже DQSMD=1.
2. **DQSMD=0 (внутренняя петля) от IN1 не зависит.** Без ошибок на обеих платах при IN1 выкл/вкл/меандр
   и во всём функциональном наборе на 135,77 и 132,92 МГц.
3. **Старая плата от IN1 не зависит ни в каком режиме:** там EXT_IN1 на AD_B1_06, не на DQS-паде.
4. **Все рабочие конфигурации чисты на обеих платах:** `legacy`, `sdram_c`, `candidate`,
   `candidate_dqsmd0`, `candidate_dqsmd0_132mhz`, `candidate_164mhz`. Удержание 30 с с refresh — чисто.
5. **Запас удержания без refresh** у обоих экземпляров близкий: первые ошибки между 1 и 5 с.

Проводка IN1 подтверждена на обеих платах (`test_in1_wiring`): M5 выкл/вкл/выкл → пин 0/1/0,
меандр доходит. На V3 в `candidate` пад занят SEMC_DQS, уровень там не читается, проводку
подтверждает тест на `candidate_dqsmd0` (`in1_check=wiring_test`).

## 2. Функциональный набор

DATABUS, ADDRBUS, MARCH C− (фон `00000000`, `55555555` без кэша, `AAAAAAAA` с кэшем),
PRNG без кэша и с кэшем. 32 МБ, холодный старт перед каждым вариантом (снятие VIN, `REN=0`).

| Вариант | SEMC, кГц | DQS | Старая плата | V3 |
| --- | --- | --- | --- | --- |
| `legacy` (production-DCD) | 135 771 | пад | ✅ 0 | ✅ 0 |
| `sdram_c` (bootloader) | 135 771 | пад | ✅ 0 | ✅ 0 |
| `candidate` | 135 771 | пад | ✅ 0 | ✅ 0 |
| `candidate_dqsmd0` | 135 771 | внутр. | ✅ 0 | ✅ 0 |
| `candidate_dqsmd0_132mhz` | 132 923 (PLL3 PFD1 /5) | внутр. | ✅ 0 | ✅ 0 |
| `candidate_164mhz` | 163 862 | пад | ✅ 0 | ✅ 0 |
| `candidate_no_refresh` (контроль) | 135 771 | пад | 0 | 1 бит (DQ7, MARCH 55555555, ≈14 с) |

Одна ошибка у `candidate_no_refresh` на V3 ожидаема: refresh выключен, MARCH идёт ≈14 с,
слабая ячейка не дожила. Это не признак неисправности платы.

## 3. Влияние EXT_IN1

Набор `in1`: PRNG 3 с кэшем и MARCH 00000000 без кэша, IN1 от M5 (оптоканал 1).

| Вариант | IN1 | Старая плата | V3 |
| --- | --- | --- | --- |
| `candidate` (DQSMD=1) | выкл | ✅ 0 / 0 | ✅ 0 / 0 |
| `candidate` (DQSMD=1) | вкл | ✅ 0 / 0 | ❌ **8 338 776 / 22 127 421**, DQ `0xFFFF` |
| `candidate` (DQSMD=1) | меандр 5 Гц | ✅ 0 / 0 | ❌ **3 736 315 / 10 735 290**, DQ `0xFFFF` |
| `candidate_dqsmd0` (DQSMD=0) | выкл | ✅ 0 / 0 | ✅ 0 / 0 |
| `candidate_dqsmd0` (DQSMD=0) | вкл | ✅ 0 / 0 | ✅ 0 / 0 |
| `candidate_dqsmd0` (DQSMD=0) | меандр 5 Гц | ✅ 0 / 0 | ✅ 0 / 0 |

Числа — ошибки PRNG / MARCH. Механизм — BOARD_DIFF §4.1: при DQSMD=1 SEMC защёлкивает прочитанные
данные по стробу, вернувшемуся через пад EMC_39. Включённая оптопара LTV-247 навязывает паду свой
уровень, строб пропадает, чтение возвращает мусор. Строб DQS участвует только в чтении, поэтому запись
этот механизм не затрагивает (отдельно не проверялось).

## 4. Удержание

Заполнить PRNG → ждать без обращений → проверить. Без кэша.

| Вариант | Выдержка | Старая плата | V3 |
| --- | --- | --- | --- |
| `legacy`, `sdram_c`, `candidate` | 1 / 5 / 30 с | ✅ 0 | ✅ 0 |
| `candidate_no_refresh` | 1 с | 0 | 0 |
| `candidate_no_refresh` | 5 с | 2 (DQ2, DQ13) | 1 (DQ10) |
| `candidate_no_refresh` | 30 с | 477, все DQ | 543, все DQ |

Предыдущий прогон старой платы в тот же день: 5 с — 1 ошибка (DQ7), 30 с — 189. Разброс между прогонами
обычный для удержания (температура в помещении, данные в ячейках).

Вывод: самая слабая ячейка держит данные 1…5 с при комнатной температуре, норма даташита — 64 мс.
Грубая оценка (удержание падает примерно вдвое на каждые +10 °C): при +50 °C — порядка 0,2…0,9 с.
Нижняя граница сравнима с полным циклом refresh у legacy-DCD (184 мс, SEMC_TIMING §3). Это довод
за кандидат (54 мс) и промышленный класс SDRAM (`-6I` / IT). Оценка грубая, при температуре не мерили.

## 4a. Запас внутренней петли по частоте (2026-09-25)

DQSMD=0, регистры SEMC как у `candidate_164mhz`, комнатная температура, функциональный набор.
V3 — два прогона (163,86 МГц — в обоих), старая плата — один.

| SEMC, МГц | V3 | Старая плата |
| --- | --- | --- |
| 132,92 | ✅ 0 | ✅ 0 |
| 135,77 | ✅ 0 (и `in1` вкл/меандр — 0) | ✅ 0 |
| 148,50 | ✅ 0 | ✅ 0 |
| 153,29 | ✅ 0 | ✅ 0 |
| 158,40 | ✅ 0 | ✅ 0 |
| 163,86 | ❌ MARCH 00000000 — 55 956 / 459 821, PRNG с кэшем — 19 / 22, MARCH AAAAAAAA — 2 / 1 | ✅ 0 |

- На V3 при 163,86 МГц ошибки только на **DQ9 и DQ15** (`dq=0x8200`), в обоих полусловах 32-битного
  слова, число плавает от прогона к прогону (MARCH 00000000: 0,06…1,35 млн, считая `in1`) — признак работы
  на самом краю. IN1 ни при чём: ошибки есть и при выключенном входе. При DQSMD=1 на 163,86 МГц чисто (§2).
- На старой плате 163,86 МГц чисто: край выше. Значит, край задаёт **разводка V3** (у DQ9/DQ15 задержка
  больше), а не кристалл или SDRAM. Длины этих дорожек можно уточнить у схемотехника — для справки,
  не блокер.

**Край на V3 — между 158,40 и 163,86 МГц. Запас на 135,77 МГц по частоте ≥ 16,7 %** (158,40 / 135,77),
на старой плате ≥ 20,7 %. Это при комнатной температуре; сдвиг края при +50 °C — следующая проверка (§5).

## 4b. FlexSPI: DQS-пад SD_B1_05 и висящая цепь LCD_DCDC_G (2026-09-25)

`tests/target/hil_flexspi_stress` + `tools/hil/09_test_flexspi_stress.py`. W25Q128, чтение Quad I/O 0xEB
(6 dummy, как LUT в FCB), 1 МБ PRNG в конце флеш, комнатная температура.

**Матрица** (AHB с кэшем 50 МБ, без кэша 5 МБ, IP 10 МБ на каждую ячейку) — обе платы, **0 ошибок везде**:

| RXCLKSRC | 30 | 60 | 80 | 99 | 120 | 133 МГц |
| --- | --- | --- | --- | --- | --- | --- |
| 1 — петля через DQS-пад (FCB) | — | ✅ | — | ✅ | ✅ | ✅ |
| 0 — внутренняя петля | ✅ | ✅ | ✅ ¹ | ✅ ¹ | ✅ ¹ | ✅ ¹ |

¹ Выше предела даташита для RXCLKSRC=0 (60 МГц, IMXRT1050IEC табл. 37) — справочно, не для production.

**Окно выборки.** DLLACR.OVRDVAL сдвигает момент выборки позже (RM 27.5.14.4, ячейка ~75–225 пс;
штатно — 1 ячейка, OVRDVAL=0). Сколько ячеек проходит без ошибок:

| Режим | Старая плата | V3 |
| --- | --- | --- |
| RXCLKSRC=1, 133 МГц (production) | 0…23 | 0…23 (+ одиночное 25 на границе) |
| RXCLKSRC=0, 60 МГц | 0…30 | 0…31 |
| RXCLKSRC=0, 99 МГц | 0…30 | 0…31 |

- Окна у плат совпадают в пределах одной ячейки. На границе первыми сбоят IO0/IO3 на обеих платах.
  **Висящая цепь LCD_DCDC_G на SD_B1_05 на чтение флеш измеримо не влияет.**
- Запас позднего края в production-режиме — 23 ячейки, то есть ≈1,7…5,2 нс при такте 7,5 нс.
  Ранний край этим способом не измерить (меньше одной ячейки задать нельзя).
- Внутренняя петля даёт окно на ~7 ячеек шире: при стробе через пад выборка уже задержана на пад.
- **Soak на V3** (production-режим, AHB с кэшем, 10 мин): 93 × 200 проходов = 18,6 ГБ, **0 ошибок**, 31 МБ/с.

## 5. Выводы для G0

По таблице G0 в PLAN.md срабатывает первая строка: **включённый IN1 ломает SDRAM**.

1. **Запасной вариант, если запас DQSMD=0 не подтвердится.** Схемотехнику: перенести EXT_IN1 с EMC_39 на свободный пин (AD_B1_05 или AD_B1_06, на V3 не заняты),
   пад EMC_39 оставить неподключённым. Данные для обоснования — §3.
2. **V3 — DQSMD=0.** Приоритетный путь (решение пользователя): без переноса EXT_IN1, без снижения
   частоты, если измерение запаса (п. 4) это подтвердит. Перенос EXT_IN1 — запасной вариант. Production-DCD (`legacy`) и текущий bootloader
   на V3 с подключённым EXT_IN1 неработоспособны: первое же срабатывание входа портит всё чтение SDRAM.
   **Текущую производственную прошивку на V3 с подключёнными входами не использовать.**
3. **Совместимый DCD для обеих ревизий не цель** (решение пользователя, 2026-09-25): DCD по ревизиям
   может различаться, DQSMD выбирается под плату.
4. **DQSMD=0 и частота.** Даташит IMXRT1050IEC Rev.2, табл. 35/36 (SEMC input timing, SYNC):
   DQSMD=0 — TIS ≥ 8,67 нс, TIH ≥ 0; DQSMD=1 — TIS ≥ 0,6 нс, TIH ≥ 1 нс. Предельной частоты для
   DQSMD=0 даташит не даёт. Ответ NXP на форуме (2026-09):
   - DQSMD=0 с внутренней петлёй допустим на кремнии **A1**, EMC_39 тогда можно использовать под другую
     функцию. У нас MIMXRT1052CVJ5B: суффикс `B` = A1 (даташит, ordering information);
   - точного максимума для DQSMD=0 нет: частоту снижают, пока выполняется входной тайминг,
     и это зависит от задержки выхода конкретной памяти.

   То есть «сколько можно» — инженерное измерение, а не число из даташита. Прямой пересчёт
   TIS 8,67 нс в частоту некорректен: точка выборки при внутренней петле внутри SEMC не документирована
   (у FlexSPI при той же TIS 8,67 нс и внутренней петле предел 60 МГц, табл. 37 — ориентир, не правило).
   Факт: DQSMD=0 чист на 135,77 и 132,92 МГц на обеих платах при комнатной температуре.
   **Запас измерен (§4a):** на V3 край внутренней петли между 158,40 и 163,86 МГц, запас на 135,77 МГц
   ≥ 16,7 % при комнатной. Окончательно — прогон при +50 и −10 °C всей лесенки `dqsmd0` (135,77…163,86):
   видно, куда сдвинулся край. Если 158,40 чист и на жаре — запас на 135,77 сохраняется. Запас зависит от задержки выхода памяти,
   поэтому на целевом W9825G6KH (фаза 1) измерение повторить. Даташит: `docs/mimxrt1052/IMXRT1050IEC.pdf`.

   Другого пада для SEMC_DQS у RT1050 нет: в RM (пин-таблица SEMC) и в SDK — только `GPIO_EMC_39` ALT0,
   регистра SELECT_INPUT у SEMC_DQS нет. Регистра подстройки задержки строба (DCCR, о котором пишет NXP
   для других RT) в RM RT1050 нет.
5. **Проверки до выпуска:**
   - прогон при −10 и +50 °C (рабочий диапазон изделия). Внутренняя петля не компенсирует
     задержку пада и платы, поэтому DQSMD=0 чувствительнее к температуре;
   - после выбора конфигурации — полный регресс на старой плате: это плата, которая уже выпускается.
6. **FlexSPI (LCD_DCDC_G на SD_B1_05, FCB 0x0C = 1)** — FCB не трогаем: RXCLKSRC=1 на 133 МГц
   (§4b). Влияния висящей цепи нет. Условие для схемотехника: LCD_DCDC_G ни к чему не подключать
   (лучше убрать цепь), SD_B1_05 под GPIO не использовать — иначе петля строба сломается, как у SEMC.
   Soak на V3 — 18,6 ГБ без ошибок. Остаётся +50 °C (блокер конца фазы 1).

## 6. Как повторить

Флеш стёрта (`just host::flash-swd-erase`), питание от VIN через M5, выход оптоканала 1 M5 — на IN1 платы.

```bash
HIL_BOARD=legacy just host::hil-sdram-stress
```

```bash
HIL_BOARD=v3 just host::hil-sdram-stress
```
