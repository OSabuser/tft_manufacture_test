# hil_hw_wdt — измерение аппаратного watchdog (плата V3.x)

RAM-прошивка для `tools/hil/07_test_hw_wdt.py` (`just host::hil-hw-wdt`).

Сторож платы МЮ.Д08.06.10 (лист 2): `LED_BLNK` (= Led_1 = `LED_HEARTBEAT`, GPIO_SD_B1_03)
→ C73 → VT8A → RC-накопитель → компаратор D8 → VT8B → VT7 → `EN` основного DC/DC BL9362.
Если LED перестаёт переключаться — питание всей платы передёргивается.
**Работает только при питании от VIN** (на стенде — M5 RLY1): компаратор питается от 4V9,
сброс идёт через EN DC/DC. От USB/5V сторож неактивен.

## Команды (UART 115200)

| Команда | Ответ | Действие |
| --- | --- | --- |
| `PING` | `PONG` | — |
| `BOOT` | `BOOT srsr=0x… wdog1=<0\|1> wdog2=<0\|1> rtwdog=<0\|1> uptime=<мс>` | причина сброса с прошлой загрузки + взведены ли встроенные сторожа |
| `FEED <period_ms> <on_ms>` | `OK` | LED горит `on_ms` в каждом периоде |
| `HOLD <ON\|OFF>` | `OK` | перестать кормить, держать уровень (ON — LED горит, пин LOW) |

После `FEED`/`HOLD` каждые 10 мс: `T <мс с момента команды>`. Последняя метка перед тишиной
в UART = таймаут сторожа.

После старта прошивка сама кормит сторожа (200 мс / 50 %), чтобы плата пережила ожидание хоста.

## Как отличаем пропадание питания

При старте прошивка читает `SRC_SRSR` и **чистит** его (w1c). Следующая загрузка видит только
то, что случилось между загрузками: `0` — сброса не было, ровно `IPP_RESET_B` (POR) — пропадало
питание, `WDOG`/`WDOG3`/`LOCKUP` — другие причины. Хост проверяет метод контрольными тестами
(без сброса → 0; снятие VIN через M5 → POR).

**Предусловие:** во флеш не прошит bootloader — его `bsp_boot_state_init()` чистит `SRSR` раньше,
чем pyOCD загрузит эту прошивку, и тогда метод слепнет (контрольный тест это ловит).
`firmware_test` или пустая флеш подходят.

Маркер в `SNVS_LPGPR0` пробовали первым — на плате V3.1 он не держится даже без сброса
(прогон 2026-09-24), поэтому отказались.

`LED_APP` (Led_2) на V3 — это `SOUND_KEY`, прошивка его не трогает (динамик отключён).
