# bsp_reset — источник последнего сброса МК (SRC->SRSR)

Отвечает на вопрос «почему плата перезагрузилась»: подача питания, внешний
вывод сброса, программный сброс, зависание ядра, watchdog, отладчик, перегрев.

> ⚠️ **Статус: НЕ подключён ни к одному образу.** Модуль пригоден только для
> ПЕРВОГО кода в цепочке загрузки, а там `SRSR` уже потребляет
> `bsp_boot_state` (см. ниже). Оставлен в дереве как готовый задел: чистый
> разбор маски и его host-тесты (`tests/host/reset`) переиспользуются, когда
> источник начнут передавать из загрузчика явно. Подробности решения —
> [PLAN.md §3.8](../../firmware/tft_app/PLAN.md).

---

## Аппаратура

| Параметр      | Значение                                                                      |
| ------------- | ----------------------------------------------------------------------------- |
| Периферия     | SRC (System Reset Controller), регистр `SRSR`                                 |
| Тактирование  | не требуется — читается сразу в `main()`                                      |
| Снятие бит    | **смешанное**: `TEMPSENSE_RST_B` — записью нуля, все прочие — записью единицы |
| Поведение бит | залипают до явного снятия (накапливаются между сбросами)                      |

---

## Очистка обязательна

`bsp_reset_capture()` читает `SRSR` и **сразу его очищает**. Без этого биты
накапливаются, и со второй перезагрузки отчёт начинает врать («сброс по
watchdog» будет висеть вечно).

Очистка идёт через `SRC_ClearResetStatusFlags()` из SDK, а не прямой записью:
у RT1052 биты снимаются по-разному (см. таблицу «Аппаратура»), и рукописное
`SRC->SRSR = mask` на этом ломается.

> Модуль пригоден для первоначального кода в цепочке загрузки, а второму и
> дальше источник должен передаваться явно (напр. через `SRC_GPR`), а не
> перечитываться из регистра.

## API

```c
void        bsp_reset_capture(void);                    /* прочитать SRSR, запомнить, очистить */
uint32_t    bsp_reset_sources(void);                    /* маска BSP_RESET_SRC_* */
uint32_t    bsp_reset_raw(void);                        /* сырой SRSR на момент capture — для лога */
const char *bsp_reset_source_name(uint32_t sources);    /* очистка: маска → причина */
```

Флаги: `POWER_UP`, `USER_PIN`, `WDOG`, `WDOG3`, `SW_OR_LOCKUP`, `OVERHEAT`,
`JTAG`, `JTAG_SW`, `CSU` — собственные флаги BSP.

Бит может быть не один. `bsp_reset_source_name()` возвращает **самый
информативный**: аварийные источники важнее штатных, потому что штатный бит
мог остаться от прошлого цикла, а аварийный означает событие. Полную картину
не теряет `bsp_reset_raw()`.

---

## Быстрый старт

```c
#include "bsp/reset.h"

int main(void)
{
    bsp_reset_capture();   /* САМЫМ ПЕРВЫМ: до всего, что может сбросить плату */
    board_hw_init();
    ...
}

/* позже, когда поднят лог: */
LOG_I("boot", "сброс: %s [SRSR=0x%08X]",
      bsp_reset_source_name(bsp_reset_sources()), (unsigned) bsp_reset_raw());
```

## Раскладка модуля

| Файл                 | Что                                                         | Host-тест                                    |
| -------------------- | ----------------------------------------------------------- | -------------------------------------------- |
| `src/reset.c`        | доступ к `SRSR`, отображение бит чипа на флаги BSP, очистка | нет (только регистры, проверяется на стенде) |
| `src/reset_decode.c` | маска → причина, приоритет — порядок строк таблицы          | да, `tests/host/reset`                       |

Разделение на две единицы трансляции — ради этого: в `reset_decode.c` нет ни
SDK-заголовков, ни регистров, поэтому логика приоритета покрывается тестами
на хосте.
